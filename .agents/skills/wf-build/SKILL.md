# 구현과 시험

요구 확인의 끝 조건을 만족한 이번 변경을 인계받는다. 독립 읽기와 대조가 끝났고, 변경이 닿는 실제 상황의 결과·근거·확인 방법이 정해졌는지 현재 요구와 원문으로 확인한다. 미정이 남아 있으면 자료 조사·기존 동작 재현으로 요구 확인을 이어 가며, 제품 코드와 새 검사 작성은 결과가 정해진 뒤 시작한다.

인계받은 입력·관찰 장소·기대값을 그대로 검사와 코드에 옮긴다. 검사에서 호출하는 앞뒤 경로의 전제까지 확정된 결과와 맞아야 한다. 구현이나 검사 도중 새 선택을 발견하면 해당 변경을 요구 확인으로 되돌린다.

확정한 기대값을 어기면 실패하는 검사를 실행하고, 실패를 고칠 만큼 구현한다. 기존 보장과 처음·반복·재개·연결된 사용 흐름도 확인한다. 상황이나 기대값이 빠지거나 검사에 미정 선택의 한쪽 결과가 들어갔다면 요구 확인으로 돌아가 근거를 해결한다. 검사가 구현과 같은 가정을 따른다는 이유로 기대값을 정당화하지 않는다.

새 사용자 선택이 생기면 `wf-ask`로 돌아간다. 확인 명령·출력·대상 상태는 `wf-ask/map.md`의 기록 도구로 보존한다. 작은 단일 작업은 직접 실행 증거를 대화에 남겨도 된다.

## 끝 조건

원래 실패와 연결된 기존 검사가 통과하고, 실제 결과를 `wf-verify`에서 원문과 대조할 수 있다. 명령을 적은 것과 실행한 것은 다르다.
