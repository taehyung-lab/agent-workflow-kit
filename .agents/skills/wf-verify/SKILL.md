# 결과 검토

판정의 근거는 요청 원문·사용자 결정·계약과 실제 관찰이다. 구현자의 자기평가는 근거가 아니다.

## 절차

1. **원문과 대조한다.** 요청 원문과 사용자 답을 다시 읽고, 요구 확인에서 다룬 실제 상황의 결과가 구현과 검사에 이어졌는지 실행 명령과 실제 출력으로 확인한다. 원문·실제 자료와 대조해 요구 기록에서 빠진 상황도 찾는다. 바꾼 코드가 지키던 기존 보장도 같다. 확인하지 못한 것은 사유·재개 조건과 함께 미확인으로 남긴다(빼거나 낮추는 것은 사용자가 정한다).
2. **확인받지 않은 결정을 찾는다.** 결과를 가르는 선택마다 요청·계약·사용자 답이 그 상황의 결과를 정하는지 대조한다. 근거로 정해진 결과는 재승인받지 않는다. 근거가 없는 사용자 몫의 선택은 `wf-ask`로 돌아가 해결한다.
3. **대표 기록의 검사를 실행한다.** 기록을 쓴 작업은 [작업 도구](work.md)의 check로 대상별 실제 검사를 실행한다. 모든 요구가 확인돼야 한다. 기록이 필요 없는 작은 작업은 직접 실행 명령과 출력을 남긴다.
4. **독립 검토를 받는다.** AGENTS.md 기본 4가 정한 작업은 반드시 받는다. 대표 기록은 작업 도구의 review로 원문·대상·검사 근거를 묶는다. 대표 기록이 없으면 원문 파일과 실제 검사 명령·출력 파일을 `verify.py prepare --request 원문 --output 검사증거`로 넘긴다(기존 수동 지도는 --map도 사용). 어느 경로든 도구가 만든 prompt_file을 별도 검토자에게 그대로 전달한다. 받은 마지막 답을 고치지 않고 대표 기록은 review --answer, 직접 경로는 `verify.py finish --round KEPT --check PASS < 검토답`으로 판정한다(--check는 실제 검사 결과). 검토자를 호출한 사실과 완료 판정은 다르다. returned는 원인을 고치고, incomplete는 미완료, unverified는 사유·재개 조건을 보고한다.

## 끝 조건

1·2가 끝났고, 미정·미확인·검사 실패가 없으며, 독립 검토가 필수인 작업은 검토까지 통과했다. 그렇지 않으면 완료라 하지 않고 남은 것을 그대로 알린다.

보고에는 요구마다 확인한 명령과 출력, 기존 계약을 따른 판단, 남은 미확인을 적는다. 지도를 쓴 작업은 다시 쓸 결정을 지도에 반영해 둔다. 승인된 후속 작업이 있으면 이어서 한다(AGENTS.md 「실행 경계」).

## 검토자 기준

판정 범위는 바꾼 동작·산출물과 연결 근거가 있는 기존 보장이다. 요구의 근거는 요구 기록의 출처(원문·사용자 결정·계약·조사 사실)다. 새 요구가 있어야 성립하는 반례는 범위 밖으로 따로 적는다.
