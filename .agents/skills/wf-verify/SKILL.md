# 독립 판정

1. 구현하지 않은 검증자가 맡는다. 개인 작업에서는 같은 모델의 별도 새 세션도 검증자가 될 수 있다. 모델이 같으면 같은 오류를 반복할 수 있으므로 실제 결과와 원문 근거로 판정한다.
   전체 담당자(작업 전체의 결과를 책임지는 쪽)는 사용자 원문(승인 메시지와 그 뒤 메시지 포함)·사용자가 승인한 때의 작업 지도 `## 기준`(승인 뒤 바뀐 기준은 사용자가 다시 승인한 것만)·대상 버전·작업 시작부터의 변경물·실행 방법·승인된 기준 변경만 골라 넘긴다. 지도의 `## 증거`와 구현자의 충족 판정·자기평가는 검증자가 자신의 독립 판정을 기록한 뒤에 대조한다.
   검증자는 먼저 확정된 조건을 원문 근거와 대조한다. 승인 뒤 사용자 메시지가 결과·범위·완료 기준을 바꿨는데 기준에 반영되지 않았으면(승인 관문이 막지 못하는 경우) 그 변경을 원문 조건으로 세워 판정한다. 조건 밖의 누락이나 근거 없이 정해진 조건을 발견하면 판정하지 않고 설계로 돌려보낸다.
2. 대상 버전·환경을 고정하고 조건별 실제 결과를 확인한다.
   - 영향받은 새 검사·기존 검사와 검사 실행 설정(실행 대상·건너뜀·실패 무시)이 변경 전후에 무엇을 보장하는지 대조한다.
   - 승인된 기준 변경은 반영하되, 유지해야 할 조건의 보장이 빠지지 않았는지와, 조건을 어긴 사례를 검사가 실패로 판정하는지 확인한다.
   - 기준 변경 항목은 그 근거를 다시 보고, 바뀐 검사가 새 기준의 충족과 위반을 구별하는지 다시 본다.
   - 판정 도중 작업 트리나 대상이 바뀌면 그 판정은 무효로 하고 다시 본다.

   합의한 필수 조건을 낮추거나 빼는 결정은 검토자가 아니라 사용자가 정한다. 구현자가 써 둔 승인 주석·파일은 독립 승인의 증거가 아니다.
   - 판정 범위는 바꾼 동작과 연결 근거가 있는 기존 보장이다. 합의 조건을 깨는 반례는 미충족으로, 새 요구가 있어야 성립하는 반례는 범위 밖 제안으로 따로 적는다(완료를 막지 않는다).
3. 판정 중 기준·제품 코드·검사를 바꾸지 않는다(검사 실행이 만드는 임시 산출물은 된다). 증거 재사용은 변경 영향과 환경이 여전히 유효한 이유가 있을 때만 한다.
4. 실패는 기대·실제·재현과 확인된 원인을 붙여 그 부분을 책임지는 곳에 돌리고, 수정된 새 버전으로 실패와 영향을 다시 판정한다. 원인 미상은 추측으로 닫지 않는다. 정한 재판정 횟수에 닿으면 미완료로 보고한다.
5. 조건마다 충족·미충족·미확인과 근거(실행한 명령과 실제 결과)를 전체 담당자에게 넘긴다. 근거가 없는 충족, 빠진 조건, 빈 답·오류는 미확인이며, 미확인·미충족이 하나라도 있으면 완료가 아니다.
