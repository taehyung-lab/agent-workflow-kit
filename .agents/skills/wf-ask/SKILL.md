# 요구 확인

## 실제 상황에서 결과까지

1. **장면을 조사한다.** `python3 .agents/skills/wf-context/context.py inspect`로 대상을 확인한다. 원문·현재 계약·지정 기준에서 실제 자료 한 건의 입력과 결과를 따라간다. 코드가 계약과 어긋나면 `context.py commit <커밋>`으로 이유를 읽는다. 확인할 수 없는 과거 사건은 미확인으로 둔다.
2. **독립적으로 읽는다.** AGENTS.md의 독립 읽기 대상이면 [reader.md](reader.md) 전문, 모든 사용자 원문, 사이에 보낸 글(결정 출처 아님), 자료 위치를 부모 대화를 상속하지 않는 독자에게 준다(fork_turns는 none). 담당자 조사와 독자의 최종 JSON을 대조한다.
3. **필요한 선택을 찾는다.** [reader.md](reader.md)의 상태 × 명령 표에 앞선 장면과 복구·반복 동작을 잇는다. 목적을 모르면 겪은 일부터 묻는다. 근거로 정할 수 없는 결과만 묻는다. 구현 세부와 결과에 영향 없는 기술 질문은 담당자가 조사한다.
4. **근거를 보존한다.** 작업 폴더 W에 합친 표·원문·독자 원본을 보존하고 후속 독자는 새 파일에 둔다. `python3 .agents/skills/wf-ask/situations.py W/situations.json --request <턴별 원문> --sent <턴별 보낸 글> --reader W/reader.json --base <시작 커밋>`으로 확인한다. 후속 독자마다 --reader를 추가한다. 대표 기록은 W/sources의 원문과 [map.md](map.md)를 쓴다.
5. **사용자에게 전달한다.** `--compose`로 정한 장면과 남은 질문을 확인한다. 선택에 따라 달라지는 실제 결과와 추천 이유를 보인다. 확정한 내용은 재승인을 요구하지 않는다. 개선 제안은 어떤 장면이 왜 좋아지는지 설명하고 채택되면 반영한다. 진행 승인은 실제 보낸 기본값에만 연결한다.
6. **이어지는 결정을 기록한다.** 질문에 대한 답은 해당 질문 뒤의 원문과 잇는다. 사용자가 먼저 결과를 바꾸면 그 장면의 ID를 유지하고 새 결과·근거를 기록한다. 후속 독자도 바뀐 장면과 유지할 장면을 원문에서 확인한다. 새 장면에는 새 ID를 준다. 뒤에서 버전을 지정하면 앞선 각 동작에도 같은 입력을 적용해 확인한다. 지정 태그는 인계 때 --reference-tag로 고정한다. 누락된 계약의 정정은 [작업 도구](../wf-verify/work.md)의 독립 근거 정정을 따른다.

## 끝 조건

입력·관찰 위치·기대값·근거가 정해질 때까지 조사·재현한다. `--handoff`로 최초 기대값과 발송 내역을 원문 옆에 고정하고 출력의 implementation(시작 자료·조작·기대값·근거)을 구현자에게 준다. 연속 사용자 발언 사이에 응답이 없으면 그 턴의 `--sent`는 빈 파일로 둔다. 검토에도 같은 원문 파일을 같은 순서로 준다. 작은 수정은 AGENTS.md를 따른다.
