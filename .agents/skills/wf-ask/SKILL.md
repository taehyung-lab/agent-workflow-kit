# 요구 확인

이번 변경이 닿는 실제 상황에서 사용자가 받을 결과를 해결한다. 결과의 근거와 확인 방법이 정해지면 구현한다.

## 실제 상황에서 결과까지

1. **대상을 조사한다.** `python3 .agents/skills/wf-context/context.py inspect`로 경로·커밋·변경을 확인하고, 요청 원문과 프로젝트 지도의 계약·환경 문서, 실제 자료와 현재 동작을 읽는다. 요청의 목표를 사용자가 어떤 입력을 주고 어디에서 어떤 결과를 보는지로 풀어 쓴다.
2. **필요한 별도 독자를 시작한다.** 독립 읽기의 필요 여부는 AGENTS.md 「작업 경로」가 정한다. 필요한 작업은 선택한 기록 방식으로 원문과 출처를 보존하고, [reader.md](reader.md) 전문 뒤에 요청 원문을 그대로 붙여 부모 대화를 상속하지 않는 별도 에이전트를 실제로 호출한다(도구에 fork_turns가 있으면 none). 요청 원문·자료 위치·독자 지침만 전달한다. 독자가 읽는 동안 주 담당자도 다음의 상황별 결과를 만든다.
3. **실제 상황에 두 결과를 넣어 근거를 대조한다.** 종류·상태·소유·처리 이력이 다른 자료를 처음 사용·반복·이미 쌓인 자료·연결 경로에 넣어 본다. 각 상황의 두 결과를 요청·계약에 각각 적용하고, 반대 결과가 깨뜨리는 정확한 약속을 찾는다. 인용한 문장이 동작을 허용할 조건, 성공 뒤 반환값, 자료 보존 중 무엇을 정하는지 구별한다. 두 결과 모두 약속을 지키면 사용자 몫이고, 하나만 지키면 그 결과와 위반 근거·확인 방법을 남긴다. 사실이 부족하면 조사하고, 사용자 결과가 같고 구현 방법만 다르면 에이전트가 정한다.
4. **독자 반환과 같은 결과 묶음을 대조한다.** 현재 요구와 출처를 보존한다. 필요한 독자의 실제 반환을 받고, 미정은 대표 기록의 `work.py record W --findings reader.json`에 그대로 추가하거나 선택한 대화 기록에 빠짐없이 보존한다. 독자가 확정한 결과도 3처럼 반대 결과를 넣어 근거를 확인한다. 한쪽에만 있는 상황과 결과가 다른 상황도 같은 묶음에 넣는다. 기록된 사용자 선택은 답의 출처로 해소한다. 뒤늦게 명시 계약을 찾아 미정 분류를 정정할 때는 [작업 도구](../wf-verify/work.md)의 독립 근거 정정 경로로 현재 원문·미정·제안 결과를 대조한다.
5. **남은 미정을 그대로 질문에 옮긴다.** 실제 사례, 근거로 정해진 부분, 두 결과의 차이, 추천과 이유를 보여 준다. 작성한 질문을 남아 있는 미정과 대조해 모든 상황의 두 결과가 전달되는지 확인한다. 독립인 선택은 묶고 앞 답에 의존하는 것은 이어서 묻는다. 조사로 확인한 사실이나 이미 정해진 결과는 재승인받지 않는다.
6. **답을 전체 흐름에 다시 넣는다.** 답이 바꾼 상황의 결과와 확인 방법을 갱신하고, 그 답 때문에 결과가 새로 갈리는 앞뒤 상황을 3~4의 같은 결과 묶음에서 해결한다. 남은 선택이 있으면 5로 돌아간다.

## 끝 조건

필요한 독자의 실제 반환과 대조를 마쳤고, 이번 변경이 닿는 실제 상황마다 무엇을 왜 바꾸고 어떤 결과가 나와야 하는지 근거 또는 사용자 결정으로 설명할 수 있으며, 입력·관찰 장소·기대값이 정해졌다. 미확인 사실과 사용자 선택이 남으면 조사·질문을 이어 간다. 질문 수나 기록 형식으로 이 판단을 대신하지 않는다.

정해진 상황과 기대값을 `wf-build`에 그대로 넘긴다. AGENTS.md 「작업 경로」에서 정한 기록 방식으로 원문·후속 답과 실제 상황의 기대값·출처를 이어 준다. 대표 기록의 사용법은 [map.md](map.md)에 있다.
