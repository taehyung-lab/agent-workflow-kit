# 요구 확인

이번 변경이 닿는 실제 상황에서 사용자가 받을 결과를 해결한다. 결과의 근거와 확인 방법이 정해지면 구현한다.

## 실제 상황에서 결과까지

1. **대상을 조사한다.** `python3 .agents/skills/wf-context/context.py inspect`로 경로·커밋·변경을 확인하고, 요청 원문과 프로젝트 지도의 계약·환경 문서, 실제 자료와 현재 동작을 읽는다. 요청의 목표를 사용자가 어떤 입력을 주고 어디에서 어떤 결과를 보는지로 풀어 쓴다.
2. **그 흐름에 실제 자료를 넣는다.** 이번 변경이 읽거나 바꾸는 자료에서 종류·상태·소유·처리 이력이 다른 대상을 찾아, 처음 사용·반복·이미 쌓인 자료·연결된 경로에 넣어 본다. 각 상황에서 무엇이 달라지고 무엇을 보존해야 하는지 설명한다. 범위는 요청한 흐름과 변경이 닿는 자료·기존 보장이다.
3. **각 상황의 결과를 해결한다.** 각 상황에서 결과를 달리 정해도 요청·계약을 지킬 수 있는지 비교한다. 두 결과가 모두 가능하면 그 문장은 선택을 정한 근거가 아니므로 사용자 몫으로 남긴다. 하나만 가능하면 다른 결과가 어기는 원문·계약·사용자 답의 문장을 붙이고 실제 확인 방법을 정한다. 현재 동작은 보존할 기존 보장과 새 기능에 택할 정책을 구별하는 자료다. 사실이 부족하면 조사하고, 사용자 결과가 같고 구현 방법만 다르면 에이전트가 정한다.
4. **독립 읽기와 대조한다(대표 기록을 쓰거나 기존 자료 처리를 바꾸는 작업).** [reader.md](reader.md) 전문 뒤에 요청 원문을 그대로 붙여 부모 대화를 상속하지 않는 별도 에이전트에게 맡긴다(도구에 fork_turns가 있으면 none). 요청 원문·자료 위치·독자 지침만 전달한다. 대표 기록의 현재 요구와 출처를 먼저 보존하고, 독자가 반환한 미정 JSON은 `work.py record W --findings reader.json`으로 그대로 추가한다. 독자의 상황별 결과·근거를 내 읽기와 대조한다. 한쪽에만 있는 상황과 결과가 다른 상황은 3으로 돌아가 해결한다. 사용자에게 물을 선택으로 기록한 것은 답을 받기 전까지 유지하며, 다음 계획에서 빼거나 같은 원문으로 확정하지 않는다. 독자가 정해졌다고 본 결과도 근거 문장이 그 상황을 실제로 다루는지 확인한다.
5. **사용자 결과가 미정인 상황을 묻는다.** 실제 사례, 근거로 정해진 부분, 선택에 따라 달라지는 결과, 추천과 이유를 보여 준다. 독립인 선택은 묶고 앞 답에 의존하는 것은 이어서 묻는다. 조사로 확인한 사실이나 이미 정해진 결과는 재승인받지 않는다.
6. **답을 전체 흐름에 다시 넣는다.** 답이 바꾼 상황의 결과와 확인 방법을 갱신하고, 그 답 때문에 결과가 새로 갈리는 앞뒤 상황을 2~3으로 해결한다. 남은 선택이 있으면 5로 돌아간다.

## 끝 조건

이번 변경이 닿는 실제 상황마다 무엇을 왜 바꾸고 어떤 결과가 나와야 하는지 근거 또는 사용자 결정으로 설명할 수 있고, 입력·관찰 장소·기대값이 정해졌다. 미확인 사실과 사용자 선택이 남으면 조사·질문을 이어 간다. 질문 수나 기록 형식으로 이 판단을 대신하지 않는다.

정해진 상황과 기대값을 `wf-build`에 그대로 넘긴다. 여러 결정·대상·인계를 유지할 때는 [map.md](map.md)의 대표 기록을 쓴다. 원문·후속 답을 보존하고 현재 요구의 기대값에 실제 상황을 담아 출처와 연결한다. 작은 단일 작업은 대화와 직접 증거로 충분하다.
