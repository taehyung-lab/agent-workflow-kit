# 요구 확인

1. `context.py inspect`(wf-context)와 AGENTS.md 「프로젝트 지도」가 가리키는 계약·환경 문서로 실제 대상·버전·사용 흐름을 확인한다. 홈에서 시작해도 각 대상의 지침을 읽는다.
2. **실제 사용 자료에서 요구를 편다.** 파일·저장 자료를 열어 이번 변경이 받는 대상의 종류·상태를 나열한다. 각 대상을 처음 처리하기·다시 처리하기·이미 쌓인 자료 처리하기·다른 명령으로 바꾸기에 넣어 보고, 그 결과를 정하는 원문이나 계약의 문장을 찾는다. 계약이 일부 결과만 정하면 나머지는 별도 선택으로 남긴다. 자료에 상태가 존재하는 사실, 현재 코드가 허용하는 사실은 새 기능의 정책을 정하지 않는다. “명세에 주요 기능이 있다”는 이유로 이 대조를 건너뛰지 않는다. 기존 자료를 바꾸거나 보존하는 기능은 별도 독자에게 [reader.md](reader.md)와 원문만 주어 같은 대조를 수행시키고, 독자가 찾은 선택은 근거 문장을 인용할 수 있을 때만 제외한다.
3. 결과·범위·권한·완료 기준이 갈리고 근거가 정하지 않은 선택만 묻는다. 실제 사례, 추천 이유, 선택에 따라 사용자가 받는 결과를 함께 설명한다. 이미 정한 사실을 승인 질문에 섞지 않는다. 사용자 결정이 남으면 조사·재현까지 하고 제품 변경은 답 뒤에 한다.
4. 답이 연 가지를 같은 방식으로 확인한다. 남은 선택이 없으면 바로 구현한다(`wf-build`). 요구를 여러 턴이나 저장소에 걸쳐 유지할 때는 [map.md](map.md)의 기록을 사용하고, [reader.md](reader.md)로 별도 독자에게 원문을 읽혀 놓친 선택을 찾는다.

## 끝 조건

사용자에게 보이는 결과를 가르는 미정이 해소됐고, 유지할 기존 보장과 확인할 기대값을 설명할 수 있다. 실제 자료·흐름마다 결과의 근거 또는 사용자 결정을 확인했다. 문서 형식이나 사용자의 승인이 요구 누락이 없다는 증명은 아니다.
