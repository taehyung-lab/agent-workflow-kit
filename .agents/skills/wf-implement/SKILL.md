# 구현

1. 작업 지도의 `## 기준`(조건·범위·기준 버전)을 현재 코드와 대조하고 달라진 연결을 확인한다.
2. 결함은 가능한 한 변경 전에 재현한다. 새 검사는 조건의 관찰 결과(화면·URL·요청·출력)를 단언해 정상·위반을 구별해야 한다(내부 호출 인자만 보는 검사로 조건을 닫지 않는다). [기존] 보존 검사를 억지로 실패시키지 않는다.
3. 최소 변경을 변경된 값을 실제로 쓰는 곳까지 연결한다. 내부 방법의 차이는 기록하고 결과·계약을 바꾸는 미정은 해당 부분만 설계로 돌린다. 승인 뒤 `## 기준`을 고치는 것은 기준 변경이므로 사용자에게 다시 묻는다.
4. 조건별 대상 버전·환경·입력·실제 결과·증거와, 검사가 그 조건을 지킨 결과와 어긴 결과를 구별하는지를 지도의 `## 증거`에 남긴다. 실환경이 필요한 조건은 대역 결과로 닫지 않는다.
5. 남은 조건과 실패 원인·수정 영향을 기록해 필요한 검증자에게 넘긴다. 인계할 때는 대상 버전·증거·작성권을 함께 넘기고 받았는지 확인한다. 직접 검사를 독립 검증으로 부르지 않는다. 검증자가 돌려보낸 결함은 원인을 고친 새 버전으로 다시 판정받는다.
