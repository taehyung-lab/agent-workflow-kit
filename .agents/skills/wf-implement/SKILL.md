# 구현

1. 인계의 조건·근거·변경 경계와 현재 작업물을 대조한다. 달라진 코드·환경과 빠진 연결은 추가 조사한다.
2. 편집 직전에 최신 파일을 확인하고 다른 작업자의 변경을 보존한다. 가장 작은 작동 경로를 실제 소비자까지 연결한다.
3. 결과와 경계를 유지하는 내부 방법은 스스로 선택하고 설계와 달라진 이유를 기록한다. 제품 선택·계약·범위 변경은 해당 부분만 보류해 확인한다.
4. 결함은 가능한 같은 조건에서 재현하고 가까운 회귀 검사를 남긴다. 관찰은 결과가 결정되는 화면·입출력·저장 상태·호출 경로에서 한다.
5. 신규·수정 수용 검사는 정상 사례와 조건 위반 사례를 구별하는지 확인한다. 변경 전 코드가 유효한 반례가 아니면 알려진 결함이나 격리된 반례를 사용하고, 확인하지 못한 판별력은 미확인으로 남긴다.
6. 승인된 수용 조건과 검사를 통과시키려 약화하지 않는다. 검사가 틀렸다면 근거를 별도 검토자에게 넘기고 관련 판정을 재확인한다.
7. 직접 검사에 대상 버전·환경·입력·관찰 결과를 연결하고 수정 영향도 확인한다. 같은 실패에 새 근거가 없거나 한도에 도달하면 미해결과 재개 조건을 보존한다.
8. 변경·설계 차이·실행 결과·남은 항목을 work.md에 갱신해 별도 검증 세션으로 넘긴다. 구현자의 직접 검사를 독립 검증으로 보고하지 않는다.
