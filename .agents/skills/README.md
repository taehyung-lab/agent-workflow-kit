# 선택 안내와 검토 도구

이 폴더는 프로젝트에 그대로 설치된다. 매 세션 읽는 기준은 저장소 맨 위 `AGENTS.md` 이고, 이 폴더에는 선택할 때만 읽는 안내([guide.md](guide.md))와 검토 도구 하나가 있다. 단계마다 자동으로 불리는 스킬도, 키트가 등록하는 훅도 없다.

| 파일 | 역할 |
| --- | --- |
| [guide.md](guide.md) | 작업 지도·질문·독립 검토를 고를 때만 읽는 안내 |
| [wf-verify/verify.py](wf-verify/verify.py) | 독립 검토 입력 묶기(prepare)·결과 판정(finish). 검토자를 띄우지 않는다 |

## 누가 무엇을 맡나

- **요청을 어떻게 이해하고 어디까지 할지**: 에이전트가 AGENTS.md 기준으로 판단한다. 분명한 실행 요청은 바로 하고, 조사·설명·리뷰 요청은 고치지 않고, 결과가 갈리는데 근거로 정할 수 없는 선택만 묻는다.
- **파일 쓰기·명령을 실제로 허용할지**: 각 도구의 권한 설정과 sandbox 가 맡는다(Claude Code 의 permissions, Codex 의 sandbox·승인 정책). 확인 창이 뜨는지는 사용자 설정을 따르고, 키트는 자기 확인 단계를 더하지 않는다.
- **결과가 맞는지**: 검사·diff 검토와, 필요할 때 아래 독립 검토가 본다.

v3.0 까지 있던 승인 관문 훅(`wf-design/approval-gate.py`)은 v3.1 에서 없앴다. 업데이트하면 설치기가 그 파일과 프로젝트 설정의 관문 훅 항목만 지운다(루트 README 「업데이트」).

## 독립 검토 도구

`verify.py prepare` 는 **요청 원문**(작업 지도 `## 기준` 의 `요청 원문` 항목, 또는 `--request` 로 준 사용자 글 그대로), **작업 지도의 `## 기준`**(있으면), **기준 커밋부터의 변경**(diff, `--base`, 기본 HEAD)을 묶고 판정 대상을 고정 복사본으로 만든다. 요청 원문을 확보하지 못하거나 지도 기준이 비면 입력 부족(미확인)으로 끝나며, 요약한 계획으로 대신하지 않는다. 검토자는 하네스의 하위 에이전트이고, 그 마지막 답을 `verify.py finish --round <kept>` 가 형식대로 판정한다.

결과: `ok`(0)만 검토 통과, `returned`(3) 원인 자리로 돌아가 고친 뒤 다시, `incomplete`(4) 재검토 한도, `unverified`(5) 빈 답·형식 오류·검토자가 대상을 바꿈·검토 중 원본이나 지도 기준 변경·입력 부족. 회차 기록은 지도 옆 `verify/` 또는 `work/review/` 에 남는다. 사용 절차는 guide.md 「독립 검토」.

한계: 지도에 옮긴 요청 원문이 사용자 글 그대로인지는 도구가 확인하지 못한다(옮기는 사람이 줄이지 않고 인용한다). 작업 전부터 있던 미커밋 변경은 기준 커밋부터의 diff 에 섞인다. 재검토 한도는 같은 요청 원문·기준 커밋 안에서 센다.

모델 없이 검토 도구를 확인하는 시험은 키트 저장소의 `evals/flowtest.py`·`evals/sandboxtest.py` 에 있다.
