# 조건과 설계
1. 관련 원문·사용자 결정·계약과 현재 입력→소유자→소비자를 조사한다. 특이한 제약의 이유와 사실·추측을 구분한다.
2. 질문에는 확인한 근거·추천·답에 따라 달라지는 조건을 붙인다. 사용자가 이미 명시한 변경은 다시 묻지 않는다. 제안된 방법보다 나은 구조가 있으면 대안·근거·대가를 밝혀 추천하고, 확정된 선택은 존중한다.
3. 새 결과와 영향받는 [기존] 조건에 번호를 붙인다. 실패·취소를 포함한 입력·관찰 장소·기대 결과·환경을 정한다.
4. 바뀐 값의 소유자와 실제 소비 경로(실행 명령·검사·생성물)를 확인하고 가장 단순한 변경 위치·이유를 정한다. 기능이나 실패 처리를 빼서 단순화하지 않는다. 새 검사의 반례와 실환경 필요 여부도 정한다.
5. 재사용할 사용자 결정은 지정 정본에 남기고, 바뀌면 그 자리에서 교체한다. 답이 나온 질문은 결정으로 바꾸고 지운다. 이력은 버전 관리가 소유한다. 인계가 필요하면 work-template.md로 담당자·한도·미정·필요한 검증을 전달한다.
