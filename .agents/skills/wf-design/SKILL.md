# 요구와 설계

1. 요청을 결과·범위로 정리하고, 지도에서 관련 원문·사용자 결정·외부 계약을 찾는다. 출처와 미확인을 구분한다.
2. 현재 코드의 입력부터 상태·데이터 소유자와 실제 소비자까지 확인한다. 특이한 제약의 이유와 이번 변경의 연결 영향을 조사하되 현재 동작을 제품 정책으로 간주하지 않는다.
3. 결과를 바꾸는 공백·충돌·범위 확대만 근거와 추천·영향을 붙여 묻는다. 사용자가 명시한 변경과 현재 코드가 다르다는 이유만으로 재승인을 요구하지 않는다.
4. 독립적으로 실패할 수 있는 필수 결과에 번호를 붙이고 중요한 실패·취소 경로를 포함한다. 영향받는 기존 요구는 근거와 함께 `[기존]`으로 표시한다.
5. 가장 단순한 변경 책임·소유자·선택 이유를 정한다. 구조 변경은 실제 중복·결합·소유권 문제를 줄이는 경우에만 포함한다.
6. 조건마다 관찰할 입력·장소·기대 결과와 필요한 환경·권한을 정한다. 직접 검사와 실제 소비 경로, 대역으로 확인할 수 없는 결과를 구분한다.
7. 전체 담당자·다음 세션·작업 한도를 정하고 이 스킬 폴더의 `work-template.md` 양식으로 `work/<작업명>/work.md`에 인계한다. 구현을 막는 미정을 명시하며 독립 부분은 먼저 진행할 수 있다.
8. 사용자 결정은 즉시 기록하고 재사용할 결정만 지정 정본에 반영한다. 문서 길이와 구현 순서는 작업에 맞게 정하되 결과와 권한을 조용히 바꾸지 않는다.
