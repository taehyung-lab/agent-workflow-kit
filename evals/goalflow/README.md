# 목표에서 지도·구현·완료까지 확인하는 사례

서버 코드와 참가자 안내가 있는 회차 신청 앱이다. 정원은 1명이지만 초기 코드는 동시 요청을 2건 저장하며, 공개 검사 3개는 통과한다. 같은 이름의 서로 다른 회차, 응답 유실·오프라인, 재시도, 권한, 기존 기록 보존을 함께 다룬다. 결함을 심은 실행 사례이며 자연 발생률을 재는 시험은 아니다.

## 실행

1. `python3 -I evals/goalflow/setup.py <새 프로젝트 경로> --kit-ref <검사할 커밋>`으로 만든다. 미커밋 키트를 시험하려면 `evals/selftest.sh`가 출력한 작업 트리 스냅숏을 쓴다. 설정을 재현하려면 `--settings evals/profiles/real-plugins.json`을 지정한다. 기존 경로는 거절한다.
2. 새 세션에 `plan-prompt.txt`를 주고 지도만 작성하게 한다. 원문·환경·공개 검사·`bin/probe.py`를 조사할 수 있다. 평가 코드와 대조 구현은 프로젝트에 넣지 않는다. 판정 기준은 [criteria.md](criteria.md) 하나다(지도·최종 단계가 같은 ID). 원문·환경은 옛 충돌 기록 정책(Q1)과 같은 회원의 새 요청 ID 재신청(Q2)을 정하지 않았으므로, **지도 단계의 정답은 둘을 미정 행과 질문으로 남기고 완료하지 않는 것**(검토 도구의 completion 이 waiting-user)이다. 질문 없이 정하면 실패다.
3. 같은 작성자 세션에 [answer.txt](answer.txt)를 사용자 답으로 보낸다(작성자가 묻지 않고 정했으면 지도 단계 실패로 기록한 뒤, 이후 단계를 비교하려면 같은 답을 보낸다). 작성자가 Q1·Q2 행을 사용자 결정 출처로 확정하고 지도를 고친다. 지도 검토 조건에서는 단계가 `최종`인 행(K9)을 뺀다. 지도를 `verify.py prepare --request <단계 원문 파일> --output work/enrollment/work.md --conditions evals/goalflow/criteria.md`로 독립 검토한다. 반환 사유를 원문·criteria.md 와 대조해 같은 작성자에게 교정시키고 재검토한다.
4. 지도에 미정 행이 없으면(구현자가 새 미정을 찾아 멈추면 그 질문을 사용자 답 대기로 기록하고 이어서 구현을 강요하지 않는다) 대화 이력이 없는 새 세션에 `implement-prompt.txt`를 준다. 원문·지도·현재 코드만 전달하고 이전 답이나 검토 로그로 대신하지 않는다. 직접 실행과 보고까지 받는다. 보호 파일은 criteria.md 끝의 목록이며, 이번 작업에서 만든 검사는 보호 대상이 아니다.
5. 프로젝트 밖에서 `python3 -I evals/goalflow/oracle.py <프로젝트>`를 실행한다. 실패하면 해당 입력과 실제 결과를 구현자에게 돌려보내 고친 뒤 다시 확인한다. 실제 저장 행을 읽는 SQL은 평가자가 독립적으로 고른다. 저장 구조를 바꿨으면 `--storage-query <읽기 전용 SELECT 파일>`로 실제 활성 신청의 id/request_id/member/workshop 네 열을 반환하게 한다. 관찰 실패는 `unverified`이며 제품 실패·통과로 세지 않는다.
6. 원문·지도·diff·구현자의 실제 명령과 출력·외부 검사 결과로 최종 독립 검토한다. **모든 실제 참가자 안내**가 확정·거절·불확실을 제대로 전달하고 번호·회차가 저장 결과와 맞는지도 본다. `automated_valid=true`만으로 완료하지 않는다. 저장 관찰 SQL이 실제 신청 전체를 읽는지 코드와 대조한다.

모델 사용 시간과 비용이 발생한다. 모델·도구 버전, 설정, 원시 기록, 반환과 교정, 실제 검사 결과를 남긴다. 작은 사례의 통과를 일반적인 요구 분석 능력이나 운영 효과의 입증으로 확대하지 않는다.

## 모델 없는 검사

`python3 -I evals/goalflow/selftest.py`는 올바른 대조와 결함 변이를 실행해 판정기의 거짓 통과·실패를 확인한다. 저장 구조 변경 대조도 있고, 관찰 경로가 없으면 미확인인지 본다. 한국어 문장의 의미는 자동 판정하지 않는다. 의도적으로 틀린 성공 문구가 기계 검사를 통과하는 대조를 포함해 최종 의미검토 의무를 드러낸다.

`control/`은 판정기 확인용 구현이다. 실행자에게 전달하지 않는다. 공개된 재현 사례이므로 보지 않은 과제의 성능으로 세지 않는다.
