# 목표에서 지도·구현·완료까지 확인하는 사례

서버 코드와 참가자 안내가 있는 회차 신청 앱이다. 정원은 1명이지만 초기 코드는 동시 요청을 2건 저장하며, 공개 검사 3개는 통과한다. 같은 이름의 서로 다른 회차, 응답 유실·오프라인, 재시도, 권한, 기존 기록 보존을 함께 다룬다. 결함을 심은 실행 사례이며 자연 발생률을 재는 시험은 아니다.

## 실행: 구성 비교

`compare.py` 가 요청부터 구현·외부 판정까지 한 번에 돈다. 키트의 채택 기준("같은 과제에서 스킬 설치 구성과 같거나 나은가")은 이것으로 잰다.

```text
python3 -I evals/goalflow/compare.py kit codex 1 <결과 폴더>      # 키트(CMP_REF 커밋, 기본 HEAD)를 설치한 프로젝트
CMP_SKILLS=<스킬 저장소>/skills python3 -I evals/goalflow/compare.py skills codex 1 <결과 폴더>   # grilling·tdd 설치 + 호출 한 줄
python3 -I evals/goalflow/compare.py none codex 1 <결과 폴더>     # 지침 없음
python3 -I evals/goalflow/table.py <결과 폴더> -v                 # 구성·회차별 통과 수, 물은 정책, 답 전 수정, 시간
```

- 세 구성은 같은 요청·정정·모의 사용자 답·마무리를 받는다. 모의 사용자는 답 전에 드러낸 선택을 인용문으로 기록한 뒤 **고정된 정책 전체**를 전달한다. 요구 발견은 답 전 인용문으로, 절차는 **결정이 남아 있는 턴의 제품 변경**으로, 최종 동작은 전달한 정책으로 따로 판정한다. `MOCK=all`은 발견을 채점하지 않는 구현 대조이며 `asked` 점수와 비교하지 않는다.
- 과제의 답에 새 정책이 포함돼도 그것을 모두 최초 요청에서 반드시 질문할 주제로 간주하지 않는다. 기본은 모든 정책 주제를 발견 대상으로 삼으며, 기존 계약·동작으로 이미 처리 근거가 있는 항목은 `discovery.json`의 `required_discovery_topics`와 빠진 주제별 `discovery_exclusions`로 근거를 명시한다. 이 파일도 과제 지문에 포함된다. 제외해도 답 전체 전달과 최종 정책 검사는 그대로 적용한다. 과거 기록에 이 정보가 없으면 당시의 모든 주제 기준을 유지한다.

- 결정 대기 턴은 과제의 `turns.json`이 이유와 함께 정한다. 없으면 정해진 사용자 글의 모든 턴이다. 예를 들어 archive-correction은 첫 요청이 목록 숨기기를 정하고, 두 번째 정정에서 보관 정책의 미정이 생긴다. 첫 요청의 허용된 변경을 나중의 위반으로 세지 않는다.
- 실행기는 턴 시작과 끝의 파일 상태 차이(`turn_changes`)와 그 턴 동안의 파일 사건(`product_touched`)을 보존한다. 이전에 허용된 턴이 만든 새 파일도 다음 턴의 관찰 대상이다. 시작 커밋 대비 전체 diff는 별도 증거다. 되돌린 편집도 사건으로 잡고 감시·기록·턴별 증거가 없으면 검토 필요다. 앱 실행 상태는 과제의 `state.txt`가 정하며 확장자로 짐작하지 않는다.
- 과거 요약에는 새 턴별 증거가 없을 수 있다. 원점수는 당시 계약으로 보존하고, 재판독은 독립 판독과 충분한 원시 증거를 별도 결과로 남긴다. 새 계약에서 증거가 없다는 이유로 통과시키지 않는다. 판정 대조는 `scenarios.py`, 턴별 관찰과 소급 실패 방지는 `tests/decision-turns.test.py`가 확인한다.

- 모델·CLI 는 [../pins.json](../pins.json) 으로 고정한다(하네스 모델, 모의 사용자 모델). 실제 CLI 버전이 다르면 실행하지 않는다.
- 원문·환경은 옛 충돌 기록 정책(Q1), 같은 회원의 새 요청 ID 재신청(Q2), 그 새 ID 의 연결(Q3)을 정하지 않았다. 판정 기준은 [criteria.md](criteria.md) 다.
- 끝나면 프로젝트 밖에서 `oracle.py` 가 실제 저장·반환값을 판정한다(15개). 관찰 실패는 `unverified` 이며 통과·실패로 세지 않는다. 저장 구조를 바꾼 결과는 `oracle.py --storage-query <읽기 전용 SELECT 파일>` 로 다시 본다.
- 결과 폴더에는 모의 사용자 분류의 입력·원시 출력(시간 초과 부분 출력 포함), 턴별 원시 기록, 요약(`<이름>.json`), 판정(`<이름>.oracle.json`), 끝난 프로젝트 파일이 남는다. 세션은 사용자 전역 설정과 격리된다.
- 일반 결과와 같은 형식의 `<이름>.meta.json` 도 남아 `python3 -I evals/report.py <결과 폴더>` 가 다른 사례와 한 표로 보인다. 사례 이름은 `goalflow`, 키트 칸은 키트 구성이면 설치한 커밋이고 스킬 설치·지침 없음 구성이면 구성 이름(`skills`·`none`)이다. 판정은 외부 판정에서 나온다: 15개가 모두 통과하고 관찰이 끝났으면 PASS, 하나라도 실패하면 FAIL, 관찰하지 못했거나 판정기가 결과를 내지 못했으면 미확인(표의 "외부 장애" 칸, 통과 분모에서 빠진다). 물은 정책·답 전 수정·실패 항목은 meta 의 `goalflow` 에 있다(`table.py` 의 `result_meta`). 새 실행은 모델·CLI·격리 설정·과제 자료·실행/판정 코드의 지문과 `fixed-policy-v1` 대화 계약을 남긴다. 비교 근거가 없거나 다르면 `report.py --compare`는 개선·퇴보를 내지 않는다. 옛 실행에 새 근거를 소급해 채우지 않는다. `check.py` 가 없는 사례라 `rejudge.py` 는 이 meta 를 다시 판정하지 않는다(종료 1 로 알린다).
- 참가자 안내 문장의 의미는 기계가 판정하지 않는다. `automated_valid=true` 만으로 전체 완료를 주장하지 않는다.

## 다른 과제

같은 실행기가 `CMP_TASK=<이름>` 으로 [tasks/](tasks) 의 과제를 돈다. 회차 신청의 요청은 "근거 없는 결정은 질문으로 남기라"고 스스로 말하므로, 아래 둘은 사용자가 흔히 쓰는 짧은 요청만 준다.

| 과제 | 요청 | 요청·운영 문서가 정한 것(given 10개) | 사용자만 아는 것(decision 4개, `answer.txt` 의 답) |
|---|---|---|---|
| `orders` 주문 할인 | 5만 원 이상 주문 10% 할인 | 기준 금액 경계, 배송비 제외, 원 미만 버림, 결제된 주문 금액 불변, 영수증 키 유지 | 기능 전에 만들어진 주문에는 적용하지 않음, 새 주문은 상품을 더하거나 뺄 때마다 다시 판단 |
| `rooms` 회의실 예약 | 겹치는 예약 막기 | 맞닿은 시각 허용, 취소 예약은 막지 않음, 옛 시각 표기(`9:30`)를 시계로 비교, 자기 예약 시간 변경 | 임시 예약은 자리를 막지 않고 확정할 때 검사, 이미 겹친 예약은 그대로 둠 |
| `labels` 표본 라벨 시트 | 시트에 표본을 담고 인쇄 확정(seal) | 12칸 경계, 확정 뒤 수정 거절, 뺀 칸 재사용, 거절한 명령은 자료 불변, 확정 반복(given 14개) | 이미 인쇄된 시트의 옛 이름 유지, 대여 표본은 담지 못함, 표본 코드 대소문자 구별(decision 6개) |
| `mill` 공동 제분소 | 작업을 만들고 run 으로 제분 | 재고 부족 거절과 자료 불변, 반복 실행, 여러 통에 걸친 경계, 작업 사이 재고 공유(given 14개) | 2/3 이 정수가 아닐 때 올림, 늦게 들어온 통부터 사용, 겨는 공동체 잔고로(decision 6개) |
| `archive-ambiguity` 할 일 보관함 | 완료된 할 일은 보관함으로 | 목록은 안 끝난 것만, 내보내기 CSV 는 모든 항목, 번호 유지, 공개 시험 | 완료해도 `archive` 명령 때 한꺼번에 옮김, `archived` 가 보관된 것만 보임 |
| `archive-correction` 할 일 보관함(정정) | 완료 항목 숨기기 → `followup.txt`: 사실 보관함으로 옮기라는 뜻 | 위와 같음 | 위와 같음 |
| `account-correction` 회원 비활성화(정정) | 회원 탈퇴 → `followup.txt`: 지우지 말고 비활성화 | 가입·로그인·명단, 비활성화 명령이 사용법에 있음, 계정 자료 유지, 다른 계정 그대로 | 비활성 계정 로그인 거절, 명단에서 빠짐, `reactivate` 로 되살림 |
| `merge-conflict` 백업 규칙 합치기 | 30일·90일 초안을 세 줄 이내로 합치기 | 파일 하나, 세 줄 이내, 새벽 3시 전체 백업 | 보관 기간 90일, 30일을 보관 기간으로 적지 않음 |

위 표의 마지막 넷은 2026-11-16 에 `evals/cases/` 의 낱말 판정 사례(질문 표지·선택 낱말로 "물었는가"를 보던 것)를 옮긴 것이다. 그 판정은 실제로 확인을 요청한 답을 실패로 채점했다.

```text
CMP_TASK=orders python3 -I evals/goalflow/compare.py kit codex 1 <결과 폴더>
```

- 판정기(`tasks/<이름>/oracle.py`)는 끝난 프로젝트의 공개 명령만 실행한다. 안내 문구와 저장 구조는 보지 않는다. 실패 항목은 given 과 decision 으로 나눠 적힌다: given 실패는 만들기·확인의 문제이고, decision 실패는 구현 결과가 전달한 사용자 정책과 다르다는 뜻이다. 답 전 발견 여부는 별도 점수다.
- `python3 -I evals/goalflow/tasks/selftest.py`(모델 없음)는 정답 구현이 전부 통과하고, 묻지 않고 흔한 쪽으로 정한 구현이 decision 항목에서 실패하는지 본다. 그 변이가 통과하는 과제는 물어야 할 것을 찾았는지를 재지 못한다.
- `labels`·`mill` 은 Codex 가 키트 지침을 읽지 않은 세션에서 출제했다(모듈 4개, 공개 검사는 통과하지만 실제 사용 순서에서 깨지는 given 항목 4개 포함). 출제 조건만 주고 숨은 결정과 판정 항목은 고치지 않았다.
- 과제를 더하면 그 과제에만 나오는 낱말을 [../leak-words.txt](../leak-words.txt) 에 넣는다.

모델 사용 시간과 비용이 든다(회당 5~10분). 현재 작업의 실패 수정·재검증을 포함한 실행 한도를 정하고 [공통 실행 원장](../README.md#실행-범위와-한도)을 같은 비교·후속 실행에 사용한다. 같은 실패를 이유 없이 반복하지 않고, 원인 분리나 전이 확인에 필요할 때만 남은 한도에서 확장한다. 작은 사례의 통과를 일반적인 요구 분석 능력의 입증으로 확대하지 않는다. `setup.py`는 프로젝트만 만들어 손으로 단계를 나눠 볼 때 쓴다.

분류 장애나 별도 의미 대조는 제품을 다시 실행하는 일과 구별한다. 독립 판독자가 정책마다 실제 인용문 또는 null을 반환하면 보존된 전체 원문과 대조할 수 있다.

```text
python3 -I evals/goalflow/discovery_review.py results/kit-codex-1.json --quotes quotes.json --reader independent-reader --method "원문과 당시 정책을 독립 대조"
```

입력은 `{"quotes":{"1":"실제 원문 인용","2":null}}`처럼 모든 정책 번호를 포함한다. 첫 턴과 정정 턴 전체를 읽으며 요약의 잘린 답을 원문으로 대체하지 않는다. 결과는 `reviews/` 아래에 원문 사본·해시·판독자·당시 과제/판정 지문과 별도로 보존한다. 인용 존재 확인은 의미 판정의 자동 증명이 아니며 기존 summary·meta·원점수는 바꾸지 않는다. 일반 결과 표의 새 실행에도 섞지 않는다.

## 모델 없는 검사

`python3 -I evals/goalflow/selftest.py`는 올바른 대조와 결함 변이를 실행해 판정기의 거짓 통과·실패를 확인한다. 저장 구조 변경 대조도 있고, 관찰 경로가 없으면 미확인인지 본다. 구성 비교의 meta 는 손으로 쓴 요약으로 통과·실패·미확인 갈래와 `report.py` 표 출력을 본다. 한국어 문장의 의미는 자동 판정하지 않는다. 의도적으로 틀린 성공 문구가 기계 검사를 통과하는 대조를 포함해 최종 의미검토 의무를 드러낸다.

`control/`은 판정기 확인용 구현이다. 실행자에게 전달하지 않는다. 공개된 재현 사례이므로 보지 않은 과제의 성능으로 세지 않는다.
