# 목표에서 지도·구현·완료까지 확인하는 사례

서버 코드와 참가자 안내가 있는 회차 신청 앱이다. 정원은 1명이지만 초기 코드는 동시 요청을 2건 저장하며, 공개 검사 3개는 통과한다. 같은 이름의 서로 다른 회차, 응답 유실·오프라인, 재시도, 권한, 기존 기록 보존을 함께 다룬다. 결함을 심은 실행 사례이며 자연 발생률을 재는 시험은 아니다.

## 실행: 구성 비교

`compare.py` 가 요청부터 구현·외부 판정까지 한 번에 돈다. 키트의 채택 기준("같은 과제에서 스킬 설치 구성과 같거나 나은가")은 이것으로 잰다.

```text
python3 -I evals/goalflow/compare.py kit codex 1 <결과 폴더>      # 키트(CMP_REF 커밋, 기본 HEAD)를 설치한 프로젝트
CMP_SKILLS=<스킬 저장소>/skills python3 -I evals/goalflow/compare.py skills codex 1 <결과 폴더>   # grilling·tdd 설치 + 호출 한 줄
python3 -I evals/goalflow/compare.py none codex 1 <결과 폴더>     # 지침 없음
python3 -I evals/goalflow/table.py <결과 폴더> -v                 # 구성·회차별 통과 수, 물은 정책, 답 전 수정, 시간
```

- 세 구성 모두 같은 세 턴을 받는다: 요청 원문([fixture/request.txt](fixture/request.txt)) → 모의 사용자의 답 → 마무리 지시. 모의 사용자는 [answer.txt](answer.txt) 의 세 정책 가운데 **에이전트가 물은 것만** 답한다(`asked.py` 가 Haiku 로 분류). 묻지 않은 정책은 알려 주지 않으므로, 물어야 할 것을 찾았는지가 외부 판정에 드러난다.
- 원문·환경은 옛 충돌 기록 정책(Q1), 같은 회원의 새 요청 ID 재신청(Q2), 그 새 ID 의 연결(Q3)을 정하지 않았다. 판정 기준은 [criteria.md](criteria.md) 다.
- 끝나면 프로젝트 밖에서 `oracle.py` 가 실제 저장·반환값을 판정한다(15개). 관찰 실패는 `unverified` 이며 통과·실패로 세지 않는다. 저장 구조를 바꾼 결과는 `oracle.py --storage-query <읽기 전용 SELECT 파일>` 로 다시 본다.
- 결과 폴더에는 턴별 원시 기록, 요약(`<이름>.json`), 판정(`<이름>.oracle.json`), 끝난 프로젝트 파일이 남는다. 세션은 사용자 전역 설정과 격리된다.
- 일반 결과와 같은 형식의 `<이름>.meta.json` 도 남아 `python3 -I evals/report.py <결과 폴더>` 가 다른 사례와 한 표로 보인다. 사례 이름은 `goalflow`, 키트 칸은 키트 구성이면 설치한 커밋이고 스킬 설치·지침 없음 구성이면 구성 이름(`skills`·`none`)이다. 판정은 외부 판정에서 나온다: 15개가 모두 통과하고 관찰이 끝났으면 PASS, 하나라도 실패하면 FAIL, 관찰하지 못했거나 판정기가 결과를 내지 못했으면 미확인(표의 "외부 장애" 칸, 통과 분모에서 빠진다). 물은 정책·답 전 수정·실패 항목은 meta 의 `goalflow` 에 있다(`table.py` 의 `result_meta`). 하네스 버전·전역 지침 지문·판정기 지문은 재지 않아 적지 않으며, `check.py` 가 없는 사례라 `rejudge.py` 는 이 meta 를 다시 판정하지 않는다(종료 1 로 알린다).
- 참가자 안내 문장의 의미는 기계가 판정하지 않는다. `automated_valid=true` 만으로 전체 완료를 주장하지 않는다.

모델 사용 시간과 비용이 든다(회당 5~10분). 구성당 3회로 시작하고, 작은 사례의 통과를 일반적인 요구 분석 능력의 입증으로 확대하지 않는다. `setup.py` 는 프로젝트만 만들어 손으로 단계를 나눠 볼 때 쓴다.

## 모델 없는 검사

`python3 -I evals/goalflow/selftest.py`는 올바른 대조와 결함 변이를 실행해 판정기의 거짓 통과·실패를 확인한다. 저장 구조 변경 대조도 있고, 관찰 경로가 없으면 미확인인지 본다. 구성 비교의 meta 는 손으로 쓴 요약으로 통과·실패·미확인 갈래와 `report.py` 표 출력을 본다. 한국어 문장의 의미는 자동 판정하지 않는다. 의도적으로 틀린 성공 문구가 기계 검사를 통과하는 대조를 포함해 최종 의미검토 의무를 드러낸다.

`control/`은 판정기 확인용 구현이다. 실행자에게 전달하지 않는다. 공개된 재현 사례이므로 보지 않은 과제의 성능으로 세지 않는다.
