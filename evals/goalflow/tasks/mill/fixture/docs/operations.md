# 운영 약속

- 기존 통의 id·곡물·입고일, 계정 id, 작업의 id·고객·곡물·투입량·상태·산출량은 임의로 고치거나 지우지 않는다. 작업 실행·취소에 따른 아래 변경만 허용한다. 과거 완료 작업의 결과와 이미 있는 잔고도 그대로 이어 쓴다.
- stock은 통 배열이며 공개 키 id, grain, grams, arrived를 유지한다. arrived는 YYYY-MM-DD 입고일이다. 같은 곡물이 여러 통에 있을 수 있다. accounts는 계정 배열이며 공개 키 id, flour, bran을 유지한다. flour와 bran은 산출물 잔고(g)다. coop은 공동체 계정이며 new의 고객으로 지정할 수 없다.
- list는 작업 배열, show/new/run/cancel은 작업 하나다. 공개 키 id, customer, grain, grams, status, flour, bran을 유지한다. grams는 투입량(g), flour·bran은 그 작업의 산출량(g)이다. status는 draft, done, cancelled다. 이 공개 키들은 유지한다. 키 추가·내부 저장 구조 변경과 배열 순서 변경은 가능하다.
- new는 알려진 고객·곡물과 양의 정수 g만 받고, 기존 번호와 겹치지 않는 번호의 draft를 만든다. 산출량은 둘 다 0이다. new만으로 재고나 잔고는 바뀌지 않는다. 이후 실행 전까지 원료를 선점하지 않는다.
- restock은 알려진 통에 양의 정수 g을 더하고 그 통 JSON을 돌려준다. 다른 통과 작업·잔고는 바뀌지 않는다.
- run은 draft의 곡물과 같은 통들에서 투입량만큼 원료를 차감하고 done으로 만든다. 투입량의 2/3를 밀가루로, 나머지를 겨로 기록한다. 밀가루는 작업 고객의 기존 잔고에 더한다. 산출량은 모두 정수 g이고 밀가루와 겨의 합은 투입량과 같다.
- 재고 충분 여부는 실행할 때 같은 곡물의 모든 통의 현재 잔량 합으로 판정한다. 기존 통의 잔량도 전부 포함하며 합과 투입량이 정확히 같으면 허용한다. 다른 곡물 통은 쓰지 않는다. 부족하면 작업 전체를 거절한다.
- 거절한 모든 명령은 stock/accounts/list/show의 공개 값을 하나도 바꾸지 않는다. 부족으로 거절된 뒤 restock하고 같은 작업을 재시도할 수 있어야 한다. 일부 통을 먼저 차감해 저장하면 안 된다.
- done에 run을 반복하면 최초 완료 작업과 같은 공개 값을 성공으로 돌려주며 재고와 잔고를 다시 바꾸지 않는다. 과거 done에도 같은 규칙이다. 완료 작업에 cancel은 거절한다.
- draft에 cancel하면 cancelled로 바꾸고 재고·잔고·산출량은 바꾸지 않는다. cancelled에 cancel은 같은 결과로 성공하고 run은 거절한다.
- 작업마다 현재 재고를 다시 본다. 두 작업을 만들어 놓아도 먼저 실행한 작업의 차감을 다음 작업에 반영한다. 같은 곡물의 작업들을 실행할 충분한 재고가 있으면, 투입량이 모두 3의 배수인 작업들의 실행 순서를 바꿔도 최종 통별 재고와 계정별 잔고는 같다.
- 모든 변경은 다음 프로그램 실행에서도 유지한다. 조회는 저장된 공개 값을 바꾸지 않는다. 없는 통·작업·고객·곡물, 잘못된 수량이나 명령 형식은 거절한다.
