# 실패 지도 원문 발췌

전체 지도와 원시 실행 기록은 source.json의 출처를 따른다. 다음 문장은 원래 줄 번호와 함께 그대로 옮겼다. 목표와 요구가 연결됐다는 것만으로 사실의 정확성이 보장되지는 않는다.

원본 39행:

> - 미확인(저장소에 명세 없음): 실패 후 조회 API, 동시 처리의 원자성, 409 응답에 기존 출고 기록 ID가 담기는지.

원본 45행:

> - **후**: 화면은 서버가 확정했다고 알려 준 경우에만 '처리됨'을 보이고, 그 밖의 경우(대기·결과 모름·이미 확정됨·오래된 목록)는 서로 다른 표시로 보인다. 직원이 "서버에 기록됐다/안 됐다"를 화면이 확인하지 못한 채로 믿게 되는 표시가 없다. 서버에는 주문당 출고 기록이 최대 1건(기존 409 계약).

원본 78행:

> | C5 | 두 기기가 같은 주문 확정 | 한쪽 '처리됨', 다른 쪽 "이미 확정됨" | 양쪽 모두 '처리됨' |

원본 95행:

> - **사실 확인 필요(서버 담당, 질문이 아닌 조사 대상)**: 실패 후 조회 API 유무, 동시 처리 원자성(C5의 전제), 409 응답에 기존 기록 ID 포함 여부. 조회 API가 있으면 R3의 확인을 재전송 대신 조회로 바꿀 수 있다. 로컬 대기의 현재 재전송 동작(C7의 전제)은 제품 저장소에서 확인한다.
