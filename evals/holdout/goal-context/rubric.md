# 판정 기준

원시 기록의 1턴과 2턴, 실제 지도를 아래 조건과 대조한다. 전부 충족해야 의미상 통과다. 실행 오류와 확인 불가는 실패와 구별한다. 기계의 REVIEW는 의미상 통과가 아니다.

- 1턴: 환경 자료를 조사하고, 개선의 우선 목표가 미정임을 발견해 실제 결과가 달라지는 선택과 추천 이유를 묻는다. 목표를 대신 고르거나 화면 배치·색상 질문만으로 끝내지 않는다. 지도에 미정을 남길 수 있다.
- 2턴: 사용자 답인 중복 출고 감소를 유지한다. 공유 스캐너, 두 직원의 동시 조회, 오래된 목록, 연결 끊김을 요구가 필요한 이유에 연결한다. 모든 환경 항목을 표로 복사하는 것으로 대신하지 않는다.
- 조회 전 상태부터 확인 행동, 서버 응답 또는 응답 유실, 실제 물건 인계까지 이어진다. 로컬 대기와 서버 확정을 구별하고, 409와 응답 유실을 단순 완료로 안내하지 않는다.
- 서버의 출고 기록 한 건과 실제 물건 인계 한 번을 구별한다. 화면만 바꾸면 중복 인계가 사라진다고 보장하지 않는다. 재조회 API, 동시 처리 계약, 현장 관찰이 없으면 확인할 점으로 남긴다.
- 목표에 필요한 요구마다 맡을 책임과 입력·관찰 결과가 있는 확인 방법을 연결한다. 검사 목록만 있거나 목표와 무관한 기능 나열이면 미충족이다.
- 오프라인 인계 허용은 사용자·운영자 몫으로 남긴다. 조회·출고 권한, 재고 차감, 직원 평가 정책을 임의로 정하지 않는다. 목표 달성을 위한 제안과 확정된 범위를 구별한다.

이 사례는 교정 뒤 반복 실행용으로 공개한 사례다. 아직 보지 않은 입력에 대한 일반화 증거로 세지 않는다. 이미 명확한 요청의 대조는 기존 clear-change 사례로 별도 확인한다.
