# 3.7.0 교정판과 합의 표 실험의 분리

교정판: `fix/v370-corrections`, v3.7.0(e1285a1)에서 직접 시작했다.
실험 보존: `redesign/agreement-outcome`, f3ca6ef. 새 합의 표와 요구별 설계·검증 확대를 포함하므로 교정판 대신 설치하지 않는다.

## 포함

- 잘못된 question-order 평가를 실제 목적지가 있는 recommend-from-context와 목표 없는 recommend-missing-goal로 교체. 후자는 의미 검토(REVIEW)를 요구한다. 정적 링크 판정은 브라우저 클릭을 보증하지 않는다.
- record의 전체 완료 판정 제거. 기존 요구 표의 읽기·미정·의존 검사는 유지한다. 호출 문서와 계약 시험도 같은 책임으로 맞춘다.

## 제외

요구·결정 별도 표, 보낸 제안·답·합의 결과 추가 열, 양방향 연결 검사, 요구별 설계 절차 확대, 독자 역할·호출 조건 교체. wf-ask/SKILL.md·reader.md·wf-build/SKILL.md는 v3.7.0과 동일하다. AGENTS.md는 「단계」 표의 결과 검토 끝 조건 한 줄만 다르다("완료 판정을 받았다" → "대조가 끝났고, 독립 검토가 필수인 작업은 검토를 통과했다": record 가 판정을 내지 않게 되어 맞춘 것이다). map.md는 같은 표를 쓰며 record 출력 설명만 바꾼다.

## 채택 근거

원래 A화면 시험에는 실제 목적지가 없었다. 바로잡은 사례에서 3.7.0도 두 모델 모두 2/2 통과했으므로 새 분석 방식의 우위로 해석하지 않는다. 상세 과거 실측은 실험 가지 docs/measurements.md와 work/agreement-outcome에 보존돼 있다. 그 숫자를 이 교정판의 실행 결과로 옮기지 않는다.

## 다음 비교가 필요한 때

기존 표로 실제 사용자 정정·거절·여러 요구에 걸친 결정을 놓친 사례가 확인될 때, 이 교정판과 새 합의 표만 더한 구성을 같은 모델·같은 입력에서 비교한다. 최종 행동·승인 전 수정·질문 부담·시간을 함께 본다. 회차 신청 반복 두 번만으로 표의 추가 가치를 판정하지 않는다. 현재는 새 표나 추가 모델 반복을 채택 조건으로 붙이지 않는다.

## 검증

교정 전 새 record 계약 시험: 91 통과·9 실패. 교정 후 검토 도구 시험 100개, 자체 시험 241개, 설치 시험 47개가 모두 통과했다. 평가 환경을 실제로 만드는 검사 3개가 삭제된 준비 파일 참조까지 확인한다. 자체 시험에는 검토 도구 100개·쓰기 경계 8개·목표 흐름 판정기 대조 18개가 포함된다. 독립 소스 검토에서도 요구 확인·독자·구현 절차와 표 파서·prepare·finish·completion이 v3.7.0과 같음을 확인했다.

위 검증은 명령 계약·설치 호환성과 변경 범위의 확인이며, 모델의 요구 분석 능력 향상이나 실행 시간 개선을 입증하지 않는다. 발행 전 모델 확인은 [measurements.md](measurements.md) 「v3.7.1」에 있다.
