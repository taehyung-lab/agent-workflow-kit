"형식이 맞는 지도"는 두 커밋의 결과물을 fa8e43f 의 `record_rows`·`quoted_request` 로 똑같이 쟀다(상태 값이 확정·미정·미확인, 확정 행에 출처, 의존 ID 존재). v3.5.0 의 Codex 는 상태 칸에 `미정(사용자 답)` 같은 글을 적어 도구가 미정 행을 하나도 읽지 못했다(그대로 검토·완료 판정에 가면 사용자 답 대기가 나오지 않는다). fa8e43f 의 Codex 는 goalflow 3회 모두 처음에 "요청 원문 없음"으로 돌려보내진 뒤 지도를 고쳐 `completion=waiting-user` 로 끝났다.

실행기를 run.py·session.py 로 옮긴 뒤(63aa150) 실제 세션 확인: answer-proceeds(2턴, 같은 세션 이어 가기) Claude·Codex 1회씩 통과, `EVALS_VERIFY=1` weight-disposable Claude·Codex 1회씩 2회차에 검토 ok·completion=verified. 옛·새 실행기의 결과 차이는 가짜 하네스 32개 시나리오에서 0건이었다.

세지 않은 것: 남은 미정 행이 정말 물어야 할 질문인지(goal-context 는 양쪽 모두 검토 필요로, rubric.md 판정을 하지 않았다), 구현 단계 결과, `evals/defects/run.sh`(고쳤지만 실행하지 않음). 사례 둘·구성당 2~3회의 작은 측정이며 요구 분석 전반의 개선으로 세지 않는다.

같은 날 조사하고 채택하지 않은 것:
- 지도에 옮긴 요청 원문을 세션 기록과 대조하는 장치: 도구 실행 때 두 하네스 모두 세션 번호(`CLAUDE_CODE_SESSION_ID`·`CODEX_THREAD_ID`)와 세션 기록 파일을 읽을 수 있음은 확인했다. 그러나 위 goalflow 지도 12건 중 원문을 옮긴 9건은 모두 글자 그대로였고, 관찰된 실패는 "옮기지 않음"(v3.5.0 Codex 3건)이며 record 가 막는다. 실패한 주장이 없어 넣지 않았다. 이 사례는 원문이 파일로 주어진 경우다(대화로 길게 주고받은 요청은 재지 않았다).
- 직접 검사 결과(`--check`)를 도구가 명령을 실행해 얻는 장치: 실행 사실이 틀린 완료 보고가 관찰되지 않아(direction.md v3.4 결정의 기록) 넣지 않았다.

## v3.0 → v3.1: 승인 관문의 효과와 관문을 걷어낸 뒤

**비용과 위험**: 승인 관문은 Codex 가 정해지지 않은 정책(예: 탈퇴 회원 재가입 허용)을 묻지 않고 정하던 실패를 0/6 → 12/12 로 바꿨다([이슈 #20](https://github.com/taehyung-lab/agent-workflow-kit/issues/20)). v3.1 은 그 기계 장치를 없앴으므로, 이 실패는 지침(기본 2)과 `archive-ambiguity`·`account-after-correction`·`ambiguous-question` 사례로 다시 재야 한다(미측정).

### 실제 사례: "묻지 않고 정한다"를 고친 과정

사용자가 "탈퇴는 지우지 말고 비활성화하라는 뜻이었어요"라고 정정하면, Codex 는 "비활성 계정은 로그인 불가, 재가입 차단" 같은 정책을 묻지 않고 정해 구현했다(0/6). 고친 순서는 이랬다.

1. 판단 문장을 바꿨다 → 효과 없음, 되돌림.
2. 실행기가 별도 검증 세션을 띄웠다 → 검증자는 잡았지만 구현자가 코드를 남김.
3. 검증 도구를 키트에 넣었다 → Codex 가 거의 실행하지 않음, 되돌림.
4. 턴 끝에 LLM 검증 훅을 붙였다 → 판정이 흔들리고 명시된 요청까지 막음, 되돌림.
5. "결정 표"를 쓰게 하고 기계로 검사했다 → Codex 가 그럴듯한 출처를 적어 통과, 되돌림.
6. **원인 자리를 다시 봤다**: 다섯 번 모두 "구현자가 해석·승인·쓰기를 다 쥔" 구조 안에서 고쳤다. 승인을 사용자 쪽으로 옮기는 승인 관문을 넣었다 → 12/12, 채택.
7. **v3.1 에서 관문을 걷어냈다**: 승인 말을 정규식으로 가리는 관문이 분명한 요청까지 한 번 더 묻게 했고, 쓰기 허용은 사용자가 이미 고른 도구 권한 설정과 겹쳤다. 결정은 사용자에게 두되 쓰기 허용은 도구 권한에 맡기고, 묻지 않고 정하는 실패의 재발 여부는 evals 로 다시 잰다(미측정).

교훈은 AGENTS.md 기본 5에 반영했다: 문장·검사를 여러 번 고쳐도 안 되면, 결정 권한이 어디 놓였는지 본다.
