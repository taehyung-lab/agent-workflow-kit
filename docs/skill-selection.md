# 스킬 선택 확인

description이나 스킬의 담당 범위를 바꿀 때, 실제 요청에서 필요한 지식을 찾고 불필요한 절차를 늘리지 않는지 확인한다. 설치 경로나 본문을 바꾸지 않은 일반 작업마다 실행하는 절차는 아니다.

## 구조 확인과 선택 확인

- **구조 확인:** 스킬 파일과 참조 대상이 존재하고 설치한 버전으로 해소되는지 본다. 설치기는 이 키트 파일을, 외부 라이브러리 키트의 연결 검사는 그 키트 링크를 확인한다.
- **선택 확인:** 새 세션이 요청을 받고 어떤 스킬을 읽었으며, 필요한 근거를 실제 결과에 사용했는지 본다. 파일 존재나 description의 단어 일치만으로 이 결과를 대신하지 않는다.

## 요청을 고르는 기준

변경한 책임에 해당하는 실제 요청, 같은 뜻의 다른 표현, 인접하지만 해당 책임이 아닌 요청을 고른다. 정답은 스킬 이름의 완전 일치보다 **필요한 책임의 누락**과 **불필요한 단계의 강제**로 판단한다. 프로젝트에 설치된 스킬과 요청의 근거를 보고 예상 범위를 먼저 적는다.

다음은 이 키트의 단계 선택을 구별하는 예다. 라이브러리·제품 역할 스킬은 해당 프로젝트에 실제로 설치된 것만 예상 범위에 넣는다.

| 요청과 전제 | 필요한 단계·역할 | 불필요하게 강제하지 않을 것 |
|---|---|---|
| README 명령 오타를 확인된 명령으로 고친다. 동작·범위는 확정돼 있다 | 해당 문서와 실제 명령 정의를 확인하고 직접 수정·검사 | wf-design·설계 인계 문서 |
| 저장 실패 후 입력을 어떻게 남길지 미정인 변경을 설계한다 | wf-design과 해당 상태·저장 책임의 역할 스킬 | 구현이나 독립 검증을 완료한 것으로 판정 |
| 확정된 설계와 관찰 조건을 인계받아 저장 오류를 고친다 | wf-implement와 변경하는 책임의 역할 스킬 | 근거 변화 없이 전체 설계 재시작 |
| 공용 세션 변경을 구현하지 않은 검토자가 판정한다 | wf-verify와 해당 계약·소비 검사 근거 | 판정 중 제품 코드 수정 |

외부 키트 스킬의 선택은 그 키트가 담당한다. 예를 들어 입력 없는 삭제 확인이 폼 관련 스킬의 책임이라면, 그 키트의 선택 확인에는 “삭제 버튼을 누르면 확인을 받게 해줘”처럼 폼이라는 단어가 없는 요청도 포함한다. 이 문서에 외부 스킬 목록이나 description 사본을 관리하지 않는다.

## 실행과 기록

1. 대상 키트 버전, 모델·런타임, 설치된 스킬, 요청과 필요한 원문 근거를 고정한다. 변경 전후를 비교할 때는 같은 입력·환경을 쓴다.
   전역 지침·스킬(예: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, 사용자 전역 스킬 폴더)은 대상 저장소 밖에서 세션에 함께 들어와, 결과를 키트 문장이 아닌 그 내용이 만들게 할 수 있다. 그러면 기준선(비교의 출발점이 되는 결과)이 오염된다. 세션에 들어온 전역 지침·스킬을 기록하고, 비교하는 실행끼리 같게 두거나 끈 상태로 실행한다.
2. 각 요청을 독립된 새 세션에 주고, 예상 스킬이나 수정한 답은 알려주지 않는다. 구현이 필요한 요청은 격리한 작업 트리에서 실행한다.
3. 읽은 스킬과 근거, 실제 결과, 누락된 책임, 불필요하게 강제한 절차를 기록한다. 단순히 스킬을 열었다고 필요한 판단을 했다고 보지 않는다.
4. 빠진 책임은 description의 진입점부터, 읽고도 잘못 판단한 경우는 본문의 기준이나 근거부터 확인한다. 무관한 요청에 반응하면 담당 범위를 좁힌다.

결과는 해당 변경의 검토 증거에 둔다. 지속적으로 재사용할 실패 사례만 담당 키트에 남기고 모든 작업의 요청을 별도 목록으로 누적하지 않는다. 한 모델·한 요청의 통과를 전체 선택 품질 향상으로 보고하지 않는다.
